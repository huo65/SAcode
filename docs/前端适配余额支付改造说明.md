# 前端适配余额支付改造说明

## 1. 背景

后端课堂展示版支付口径已调整为“余额充值 + 余额支付 + 退款回滚”：

- 顾客通过余额充值模拟第三方支付入账。
- 顾客下单后使用余额支付。
- 后端统一完成订单金额计算、余额扣减、库存扣减、订单状态更新、钱包流水和审计记录。
- 退款或商家取消订单时，通过订单状态机触发余额回滚、库存恢复、退款流水和审计记录。
- 支付宝沙箱不进入课堂展示主链路，仅作为后续第三方支付扩展。

因此前端也需要同步展示口径，避免页面继续引导用户进入支付宝沙箱流程。

## 2. 当前前端不匹配点

| 位置 | 当前情况 | 需要调整 |
| --- | --- | --- |
| `src/components/goods/pay.vue` | 支付弹窗仍提供“模拟支付 / 支付宝”两种方式 | 改为“余额支付”，移除支付宝选项和二维码 |
| `src/components/goods/cart.vue` | 购物车支付仍存在 `alipay` 分支，会打开 `/alipay/pay` 并轮询 `/alipay/check` | 删除支付宝分支，只调用 `/user/pay` |
| `src/components/goods/detail.vue` | 商品详情直接购买仍存在 `alipay` 分支 | 删除支付宝分支，只调用 `/user/pay` |
| `src/api/apis.js` | 仍暴露 `Alipay.pay`、`Alipay.check`，缺少钱包接口 | 新增充值、钱包查询、钱包流水接口；支付宝接口可保留但不用于主链路 |
| 顾客页面 | 没有明确的余额充值入口 | 增加“充值余额”入口或在支付弹窗内提供快捷充值 |
| 管理端/治理页 | 没有钱包流水展示入口 | 可增加管理员钱包流水查询面板，用于答辩展示支付审计 |

## 3. 建议新增前端 API

在 `src/api/apis.js` 的 `User` 和 `Ops` 中补充：

| 模块 | 名称 | 方法 | 地址 | 用途 |
| --- | --- | --- | --- | --- |
| `User` | `recharge` | `post` | `/user/recharge` | 顾客充值余额，管理员可给指定用户调账 |
| `User` | `wallet` | `get` | `/user/wallet` | 查询当前用户余额、累计充值、累计支付、累计退款和最近流水 |
| `User` | `walletTransactions` | `get` | `/user/wallet/transactions` | 查询当前用户钱包流水 |
| `Ops` | `walletTransactions` | `get` | `/ops/wallet/transactions` | 管理员查询平台钱包流水 |

## 4. 最小前端改造范围

### 4.1 支付弹窗

目标文件：`src/components/goods/pay.vue`

建议调整：

1. 标题改为“余额支付”。
2. 移除支付宝单选项、二维码、支付宝提示文案。
3. 展示余额支付说明：
   - “将使用账户余额完成支付。”
   - “余额不足时请先充值。”
4. 按钮文案改为“确认余额支付”。
5. 事件仍可沿用 `emit("pay", "wallet")` 或直接 `emit("pay")`。

### 4.2 购物车支付

目标文件：`src/components/goods/cart.vue`

建议调整：

1. 删除 `startAlipayPayment` 相关逻辑。
2. 删除对 `Alipay` API 的导入。
3. `finishPay` 不再判断 `payWay === "alipay"`。
4. 统一调用 `Order.payOrder2`，请求体保持：

```js
{
  orderIdList
}
```

5. 支付成功后刷新购物车、订单列表或跳转订单页。

### 4.3 商品详情直接购买

目标文件：`src/components/goods/detail.vue`

建议调整：

1. 删除 `startAlipayPayment` 相关逻辑。
2. 删除对 `Alipay` API 的导入。
3. `payBill` 统一调用 `Order.payOrder2`。
4. 支付失败时直接展示后端错误，例如“余额不足”“订单状态不允许支付”“库存不足”。

### 4.4 充值入口

可选位置：

- 顾客个人信息页：`src/components/info/index.vue`
- 支付弹窗：`src/components/goods/pay.vue`
- 顾客首页头部用户信息区域

建议最小方案：

1. 在支付弹窗展示当前余额。
2. 如果余额不足或用户主动点击“充值”，弹出充值金额输入框。
3. 调用 `User.recharge`。
4. 充值成功后刷新 `User.wallet` 和用户信息。

### 4.5 钱包流水展示

顾客端建议：

- 在个人信息页增加“钱包余额”和“最近流水”。
- 展示流水类型：充值、支付、退款。

管理端建议：

- 在治理与经营页面增加“钱包流水”列表。
- 可按用户、类型筛选。
- 用于课堂展示支付审计能力。

## 5. 前端展示文案建议

统一口径：

- “课堂展示版采用账户余额模拟第三方支付。”
- “充值表示第三方支付入账，支付表示订单扣款，退款表示余额回滚。”
- “支付宝沙箱作为后续第三方支付扩展，本次演示不进入主链路。”

避免继续出现：

- “打开支付宝”
- “支付宝沙箱支付页”
- “支付完成后自动刷新支付宝状态”

## 6. 验收清单

| 场景 | 操作 | 预期结果 |
| --- | --- | --- |
| 余额查询 | 顾客进入支付弹窗或个人信息页 | 能看到当前余额 |
| 余额充值 | 顾客输入充值金额并确认 | 余额增加，产生 `RECHARGE` 流水 |
| 余额支付成功 | 顾客余额充足时支付订单 | 余额扣减，订单进入商家待处理状态，产生 `PAY` 流水 |
| 余额不足 | 顾客余额不足时支付 | 前端展示后端错误，并提示先充值 |
| 商家取消订单 | 商家拒单或取消备餐中订单 | 顾客余额回滚，库存恢复，产生 `REFUND` 流水 |
| 顾客查看流水 | 顾客查看钱包流水 | 能看到充值、支付、退款记录 |
| 管理员查看流水 | 管理员进入治理页查看钱包流水 | 能看到平台钱包流水 |
| 支付宝入口 | 检查支付弹窗和主流程 | 不再出现支付宝主链路入口 |

## 7. 建议实施顺序

1. 先改 `apis.js`，补齐钱包接口。
2. 改 `pay.vue`，统一为余额支付弹窗。
3. 改 `cart.vue` 和 `detail.vue`，移除支付宝分支。
4. 增加充值入口和余额展示。
5. 增加顾客钱包流水展示。
6. 视展示需要补管理员钱包流水面板。
7. 跑前端构建和主链路联调。

## 8. 与后端对应关系

| 前端动作 | 后端接口 | 后端效果 |
| --- | --- | --- |
| 充值余额 | `POST /user/recharge` | 增加余额，写入 `RECHARGE` 流水，记录审计 |
| 查询钱包 | `GET /user/wallet` | 返回余额、累计充值、累计支付、累计退款、最近流水 |
| 查询个人流水 | `GET /user/wallet/transactions` | 返回当前用户钱包流水 |
| 支付订单 | `POST /user/pay` | 扣余额、扣库存、更新订单状态、写入 `PAY` 流水 |
| 商家/管理员退款 | `POST /order/update` | 退款回滚余额、恢复库存、写入 `REFUND` 流水 |
| 管理员查流水 | `GET /ops/wallet/transactions` | 返回平台钱包流水 |
