# 后端功能地图与前端页面设计参考

## 1. 文档用途

本文按角色整理当前后端已实现能力，供后续前端大改时作为页面设计参考，避免漏掉课堂展示需要呈现的功能。

当前后端目标是课堂展示级外卖订单系统，主线为：

`商家维护门店与商品 → 管理员审核商品 → 顾客浏览餐厅并下单 → 顾客充值余额并支付 → 商家接单备餐 → 骑手接单配送 → 顾客确认收货评价 → 售后/退款/审计闭环`

支付口径已确定：

- 课堂版采用钱包余额模拟第三方支付。
- 充值代表第三方支付入账。
- 余额支付代表订单扣款。
- 退款通过订单状态机触发余额回滚、库存恢复、退款流水和审计。
- 支付宝沙箱只作为后续扩展，不进入课堂展示主链路。

## 3. 公共基础能力

### 3.1 登录注册与用户信息

| 能力 | 接口 | 说明 | 页面设计建议 |
| --- | --- | --- | --- |
| 登录 | `POST /user/login` | 返回 JWT 和用户信息 | 登录页；成功后根据角色跳转不同首页 |
| 注册 | `POST /user/register` | 支持顾客、商家、骑手等角色注册 | 注册页；角色选择应清晰 |
| 当前用户信息 | `GET /user/getinfo` | 普通用户查自己，管理员可查指定用户 | 个人资料页、顶部用户信息 |
| 更新用户信息 | `POST /user/update` | 用户改自己资料，管理员可改用户 | 个人资料编辑 |
| 地址列表 | `GET /user/address` | 普通用户查自己地址，管理员可查指定用户 | 地址管理、下单地址选择 |
| 添加地址 | `POST /user/addAddress` | 添加当前用户地址 | 地址弹窗/地址管理 |
| 删除地址 | `DELETE /user/deleteAddress` | 删除指定地址；空参数仅管理员可清空 | 地址管理 |

### 3.2 文件上传

| 能力 | 接口 | 权限 | 页面设计建议 |
| --- | --- | --- | --- |
| 上传图片 | `POST /storage/upload` | 登录后可上传；商家可上传商品图/门店图，顾客可上传头像 | 商品编辑、门店资料、个人头像 |
| 图片访问 | `GET /storage/**` | 公开读取 | 所有图片回显 |

上传限制：

- 只允许图片类型。
- 单文件不超过 5MB。
- 顾客主要用于头像。
- 商家用于头像、商品、门店图。
- 管理员不受 category 限制。

## 4. 顾客端功能地图

### 4.1 顾客首页：餐厅与商品浏览

| 能力 | 接口 | 关键参数/数据 | 页面设计建议 |
| --- | --- | --- | --- |
| 餐厅列表 | `GET /restaurant/list` | `keyword`、`category`、`sortBy`、`onlyOpen`、`minScore` | 顾客首页主入口；展示门店名、Logo、封面、评分、标签、起送价、配送费、预计送达 |
| 餐厅详情 | `GET /restaurant/info` | `id` | 餐厅详情页；展示公告、营业状态、菜单分类、商品列表、评价摘要 |
| 商品搜索 | `GET /product/search` | 分类、名称、价格区间、排序、状态 | 可作为餐厅内搜索或全局商品搜索 |
| 商品详情 | `GET /product/info` | `productId` | 商品详情弹窗/页面 |

后端餐厅核心字段：

- `name`：门店名称
- `logo`、`cover`：门店图片
- `description`：简介
- `notice`：公告
- `status`：营业状态
- `businessHours`：营业时间
- `deliveryFee`：配送费
- `minOrderAmount`：起送价
- `serviceRadiusKm`：配送范围
- `deliveryEtaMinutes`：预计送达
- `featureTags`：标签
- `menuCategories`：菜单分类
- `addressText`：门店地址
- `deliveryPolicy`：配送说明
- `promoText`：活动文案

### 4.2 购物车与下单

| 能力 | 接口 | 说明 | 页面设计建议 |
| --- | --- | --- | --- |
| 查询购物车 | `GET /cart/getCart` | 当前顾客购物车 | 购物车抽屉/页面 |
| 更新购物车 | `POST /cart/update` | 批量提交购物车项 | 数量加减、删除商品 |

下单页面建议展示：

- 数量

- 收货地址

- 库存不足、商品未审核、地址缺失等错误提示

### 4.3 钱包充值与余额支付

| 能力 | 接口 | 说明 | 页面设计建议 |
| --- | --- | --- | --- |
| 查询钱包 | `GET /user/wallet` | 返回余额、累计充值、累计支付、累计退款、最近流水 | 支付弹窗、个人钱包页 |
| 充值余额 | `POST /user/recharge` | 顾客只能给自己充值；管理员可指定用户 | 支付弹窗快捷充值、个人钱包页充值 |
| 个人钱包流水 | `GET /user/wallet/transactions` | 顾客只能看自己流水 | 钱包流水列表 |
| 支付订单 | `POST /user/pay` | 请求体传 `orderIdList`；扣余额、扣库存、写支付流水 | 支付弹窗确认余额支付 |

钱包流水类型：

- `RECHARGE`：充值入账，金额为正
- `PAY`：余额支付，金额为负
- `REFUND`：退款回滚，金额为正

支付弹窗建议：

- 显示订单金额
- 显示当前余额
- 余额不足时显示充值入口
- 支付成功后刷新订单状态和钱包余额
- 不再展示支付宝入口

### 4.4 顾客订单

| 能力 | 接口 | 说明 | 页面设计建议 |
| --- | --- | --- | --- |
| 查询订单 | `POST /order/get` | 当前顾客查自己的订单；支持状态和时间排序 | 我的订单页 |
| 申请退款 | `POST /order/update` | 目标状态 `-2`，需退款原因 | 订单卡片“申请退款” |
| 确认收货 | `POST /order/update` | 目标状态 `2` | 配送中订单“确认收货” |
| 提交评价 | `POST /review/add` | 完成订单后评价 | 评价弹窗 |
| 提交售后工单 | `POST /afterSale/create` | 投诉、退款、配送问题等 | 售后入口 |
| 查询售后 | `GET /afterSale/list` | 顾客自己的工单 | 订单卡片展示工单状态 |
| 售后统计 | `GET /afterSale/stats` | 当前角色范围统计 | 可用于个人售后概览 |

订单状态建议映射：

| 状态 | 含义 | 顾客可见操作 |
| --- | --- | --- |
| `-3` | 已退款 | 查看退款结果、钱包流水 |
| `-2` | 退款中 | 等待商家/管理员处理 |
| `-1` | 待支付 | 去支付、取消展示可后续补 |
| `0` | 已支付/待商家接单 | 等待商家处理 |
| `4` | 备餐中 | 等待出餐，可申请退款 |
| `3` | 待骑手接单 | 等待骑手接单 |
| `1` | 配送中 | 确认收货、申请退款/售后 |
| `2` | 已完成 | 评价、售后 |

## 6. 骑手端功能地图

### 6.1 配送订单

| 能力 | 接口 | 状态流转 | 页面设计建议 |
| --- | --- | --- | --- |
| 查询骑手订单 | `POST /order/get` | 返回待接单或当前骑手负责的订单 | 骑手首页 |
| 接单 | `POST /order/update` | `3 → 1`，绑定当前骑手 | 待接单列表“接单” |
| 拒绝/退回配送池 | `POST /order/update` | `1 → 3`，仅当前骑手可退回 | 配送中订单“退回/拒单” |
| 配送完成后等待顾客确认 | 顾客操作 `1 → 2` | 骑手端展示配送完成提示即可 | 配送中列表 |

骑手端建议页面：

- 待接单订单列表
- 我的配送中订单
- 已完成/历史订单
- 订单详情：取餐地址、收货地址、顾客/商家名、商品摘要、状态

当前后端限制：

- 骑手只能接 `state = 3` 的订单。
- 同一骑手如果已有配送中订单，则不能再接第二单。
- 只有当前绑定骑手能退回配送池。
- 地图导航目前是前端占位能力，真实地图和路线规划属于后续增强。

## 8. 订单状态机总览

| 状态值 | 状态名 | 主要触发角色 | 典型前端动作 |
| --- | --- | --- | --- |
| `-3` | 已退款 | 商家/管理员 | 确认退款、商家取消订单 |
| `-2` | 退款中 | 顾客 | 申请退款 |
| `-1` | 待支付 | 顾客 | 下单成功后待支付 |
| `0` | 已支付/待商家处理 | 顾客支付后 | 商家接单或取消退款 |
| `4` | 备餐中 | 商家 | 接单/开始备餐 |
| `3` | 待骑手接单 | 商家/骑手 | 商家推送骑手池；骑手退回池 |
| `1` | 配送中 | 骑手 | 骑手接单 |
| `2` | 已完成 | 顾客 | 确认收货 |

建议前端把状态机做成统一工具，避免各页面重复写状态文案和按钮条件。

## 10. 当前后端空白或后续增强

这些能力目前不应作为前端主展示承诺：

- `MessageController` 仍为空壳，消息通知可先作为后续增强。
- 支付宝沙箱接口保留但不进入课堂主链路。
- 真实地图导航、经纬度路线规划、自动派单算法仍是后续增强。
- 分页、缓存、监控、备份、CI、E2E 仍是质量增强方向。
- 优惠券、满减、广告投放等营销能力尚未形成完整后端闭环。
