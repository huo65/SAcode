# 需求进度与后续计划

## 1. 开发目标

最终目标是完成两份课程实践 PPT 中提出的“美团外卖订单系统”需求，达到课堂展示级即可。展示重点不是复刻真实美团，而是让系统能围绕分层架构讲清楚四端业务闭环、关键质量属性、架构风险和后续演进方向。

课堂展示级定义：

- 页面可进入，核心功能可操作。
- 主链路可从商家上架走到顾客下单、配送、收货和评价。
- 重要后台能力可展示，包括用户/权限、售后、经营分析和审计。
- 企业级能力可以用“已实现基础能力 + 后续增强计划”的方式说明，不强行伪装为生产级。

## 3. 当前开发进度

### 3.1 已达到课堂展示级的能力

- 四端入口：顾客、商家、骑手、管理员角色均有页面入口。
- 认证基础：JWT、登录态、角色上下文、密码哈希迁移已有实现。
- 商品与餐厅：商家商品管理、管理员审核、餐厅列表/详情、门店资料维护已有实现。
- 订单主链路：购物车/直接下单、后端金额计算、余额充值、余额支付、钱包流水、库存扣减、防超卖、退款回滚、状态流转已有实现。
- 配送链路：骑手接单、拒单回池、在线/忙碌、收入明细、异常上报、导航占位已有实现。
- 评价与售后：顾客评价、商家回复、售后工单、商家处理、管理员总控已有实现。
- 经营治理：平台看板、商家经营分析、RBAC 权限矩阵、审计日志、CSV 导出已有实现。
- 测试基础：后端已有 `AfterSaleServiceImplTests`、`OperationsServiceImplTests`、`OrderInfoServiceImplTests`、`OrderReviewServiceImplTests`、`PasswordUtilTests`、`RestaurantServiceImplTests`、`WalletServiceImplTests` 等测试；前端已有 `orderDriverHelper.test.mjs`。

## 4. 后续完善计划

### 4.1 第一阶段：演示前必做

1. 按 [课堂展示联调验收清单](课堂展示联调验收清单.md) 跑通一轮主链路。
2. 复核四个演示账号：`admin`、`customer`、`merchant`、`driver`，密码均为 `123456`。
3. 确认 `driver` 角色页面可以正常加载、接单和完成配送。
4. 验证商品图/门店图上传、落盘、回显。
5. 按已确定口径展示支付：
   - 顾客先通过余额充值模拟第三方支付入账。
   - 下单后使用余额支付，后端完成余额扣减、库存扣减、钱包流水和审计记录。
   - 退款或商家取消订单时展示余额回滚、库存恢复和退款流水。
6. 运行 `mvn test` 和 `npm run build`，把结果记录到验收清单。

### 4.2 第二阶段：业务体验增强

1. 支付：补支付失败重试、取消支付、超时未支付、到付方式；支付宝沙箱作为第三方支付扩展，不进入课堂主链路。
2. 消息：补最小订单通知/客服通知，避免 `MessageController` 长期为空壳。
3. 权限：继续收紧消息、支付扩展、订单状态更新等接口的角色边界。
4. 前端：补加载态、空状态、错误态和移动端适配，清理重复 UI。
5. 骑手：补真实地图、取餐/送达路线、自动派单或手动派单策略。

### 4.3 第三阶段：质量与交付增强

1. 后端增加商品、订单、日志列表分页。
2. 增加健康检查、监控指标、备份恢复说明。
3. 建立 API 文档或 OpenAPI 描述。
4. 增加前端关键流程 E2E，建立 CI 构建与测试流水线。
5. 清理历史乱码注释、旧接口命名和敏感配置。

## 5. 答辩讲解建议

演示顺序建议：

1. 管理员查看平台看板和权限矩阵，说明分层架构与治理能力。
2. 商家维护门店资料并新增商品。
3. 管理员审核商品。
4. 顾客浏览餐厅、下单、支付。
5. 商家接单并推送给骑手。
6. 骑手接单并完成配送。
7. 顾客确认收货、评价，商家回复。
8. 顾客提交售后，商家或管理员处理。
9. 回到经营分析和审计日志，说明数据闭环。

答辩口径建议：

- 已完成的是课堂展示级四端闭环。
- 第三方支付、监控、备份、压测、CI 等企业级能力按后续计划推进；课堂版支付重点展示余额充值、余额支付、退款回滚和审计。
- 架构上坚持分层设计，未来可把支付、配送、消息、文件存储逐步拆成独立服务。
